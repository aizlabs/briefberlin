# Host scheduling and editor review

The default mode is observation. Install the policy from `config/editorial_policy.yaml` or set `BRIEFBERLIN_EDITORIAL_POLICY` to a complete private copy. Configure `editor_allowlist` with URL-escaped identity components joined by slashes, in transport/account/conversation/sender order. For example, `telegram/desk/-123/456` identifies sender 456 in conversation -123 on the desk account. A slash within a component becomes `%2F`. The default allowlist is empty.

### Host trust boundary

The operator installs an authenticated inbound transport adapter and a private review service. Give the adapter and verifier an identical, securely generated 32-byte binary key in private regular files (mode 0400 or 0600). Set `BRIEFBERLIN_REVIEW_KEY_FILE` in their trusted service environments. Protect service executables, policy, outbox, agent tool definitions and the database including its directory, WAL and journal with OS permissions. Run the model, its shell and its tools under a separate restricted identity without access to any of these writable resources, keys, publisher credentials, worker tokens or the administrative CLI. Expose only narrowly scoped service operations it needs for the task. The signer has no callable model-facing endpoint. A shared unrestricted host shell defeats this boundary.

The operator CLI, direct Python APIs, low-level `triage-rate` and case-resolution commands are trusted administration interfaces. Only the signed `review-action` interface processes transport review decisions. Run the callback verifier with a service-owned key, policy and database path. Keep its executable arguments and environment fixed when exposing it through a service. An editor identity supplied by a model, an arbitrary script under that service account, or a user-supplied environment is insufficient evidence of an authenticated transport event.

## Host commands

```sh
briefberlin-editorial init
briefberlin-editorial dispatch-mode observe
briefberlin-editorial archive-sync --output output
briefberlin-editorial dispatch-tick
briefberlin-editorial dispatch-status
briefberlin-editorial review-pending
briefberlin-editorial review-resend
briefberlin-editorial review-delivered --request REQUEST --receipt TRANSPORT_DELIVERY_KEY
briefberlin-editorial review-action < trusted-callback.json
briefberlin-editorial publish-pause
briefberlin-editorial publish-resume
```

Bootstrap the host archive with the explicit seed in the [archive instructions](editorial-triage.md). For a fresh host perform bootstrap before polling. Schedule the dispatcher every `tick_seconds` (default 300). First reconcile outstanding publisher operations from their durable manifests, then refresh the live archive from the current checkout, then run the tick. `archive_max_age_seconds` defaults to 600. Failed, missing, empty or old archive state prevents new claims and push authorization. A routine sync temporarily blocks these operations and preserves valid pre-push work. Changing mode or automatic pause supersedes automatic preparations and cards. Resuming automatic dispatch requires a successful archive sync started after the last control change. Explicitly approved manual work can use any current reconciled archive in either mode, including during automatic pause. Every external attempt remains reserved until reconciled. The host's separate `collection-pause` command controls polling.

`dispatch-mode live` requires an editor allowlist and a private key. Before activation, the operator must verify the deployed adapter authenticates transport events, resolves delivered controls from its private outbox, rejects altered callbacks, and keeps these privileges isolated from the model. Install the stage 5 worker and verifier first. Stay in observation until those checks pass on the host.

In observation, ticks can write private simulated cards and receipts. An allowed simulated approval yields `would-publish`. Simulated ratings and holds apply to that evidence version in observation. Production dispatch ignores those overrides. A simulated hold lasts `hold_seconds`, independently of the review interval. A simulated decline excludes that revision from subsequent suggestions. The review bridge checks both mode and `deliver`. `review-pending` reports whether a pending live card still needs delivery. The host uses a durable outbox/idempotency key per request to recover ambiguous transport sends. `review-resend` permits an explicitly requested repeat of the same pending card. Use a globally distinct receipt including transport/account/message identity. A lost receipt replay returns the original acknowledgment.

The host adapter persists an immutable `scripts.editorial.review_adapter.Control(request_id, story_id, version, verb, rating)` for every delivered button under its transport, account, conversation, message ID and opaque control ID. On an authenticated inbound event, call `review_adapter.signed_event(metadata=..., event_id=..., message_id=..., control_id=..., lookup_control=...)` with identities from the authenticated transport and a lookup of that exact outbox tuple. Each rating option has its own bound numeric value. The adapter passes the returned envelope directly to the verifier. The signing key, callback envelope and raw event stay inside the trusted services. Stage 4 supplies the transport-independent hook and verifier. The host supplies transport authentication, the durable outbox and the service identity separation.

The envelope has this wire shape. Only `rating` and `note` are optional inside the payload. The signature is lowercase HMAC-SHA256 over the ASCII bytes of `briefberlin/review-action/v1`, one zero byte, and the ASCII JSON serialization of the entire payload with recursively sorted keys, ASCII escaping and comma/colon separators without whitespace (`review.callback_bytes`). Distinct events on the same transport/account use distinct event IDs. Verify the signature and allowlist before looking up receipts. An exact replay returns its recorded final result. A temporary `retry` binds the event to its original contents while allowing the identical signed event to be processed when the block clears. Reusing the event ID with another actor or a changed decision is rejected.

```json
{"payload":{"metadata":{"transport":"telegram","account":"desk","conversation":"-123","sender":"456"},"event_id":"update-245","request_id":"CARD_ID","story_id":"STORY_ID","version":2,"verb":"rate-and-publish","rating":8,"note":"Immediate local effect"},"signature":"<64 lowercase hex characters from the authenticated adapter>"}
```

Valid verbs are `rate`, `approve`, `rate-and-publish`, `decline` and `hold`. Supply an integer rating only for the two rating actions. An approval is tied to the exact evidence version and open slot. Rating alone retains the approval requirement, including a change to 9 or 10. An explicit rate-and-publish accepts 4–10. A decline preserves the disposition on the story and defers another suggestion until at least one review interval has passed. A hold defers that story for `hold_seconds`. Only a trusted explicit manual decision can publish a superseded or declined case.

## Selection and evidence

A serialized tick selects one globally active publication worker. Scores 9–10 qualify for immediate publication. Otherwise the slot opens exactly 43,200 UTC seconds after the one recorded live clock. Scores 7–8 compete on score, earliest reader deadline, evidence freshness and story ID. Tier 0 ties use evidence freshness then ID. Scores 4–6 may receive a single card if no higher candidate qualifies. Unanswered cards remain pending while current. A review interval of 43,200 seconds limits repeat suggestions in the open slot. A new Tier 0 supersedes an unpushed fallback; a running Tier 0 finishes before the next Tier 0 is claimed.

The candidate needs a sufficient current attributable evidence revision, a future expiry and any applicable reader deadline. Holds, manual drafts, retry deferrals, known live events, flagged corrections and incomplete cases are excluded. An expired window closes eligibility even when the last stored model disposition is pending. For reconsideration collect a newly dated report or a substantive notice revision and triage a material change for the same story. A new model decision can revise an expired or skipped model disposition and keeps the original queue age. A new sighting of identical text does not refresh a candidate. Material changes before push invalidate the reservation and any earlier approval. During an authorized push the frozen material remains unchanged; corrections go to editor review. An absent reconciled push that received a material correction can be reassessed through `triage-resolve --owner EDITOR --story ID`.

## Stage 5 publication contract

Use a connection from `scripts.editorial.db.connect` and these Python functions from `scripts.editorial.dispatch`. Each function owns a short transaction. Perform generation, filesystem and network work outside it. Omit `now` in host code; CLI takes no simulated clock argument. `work_id` identifies a reservation and `token` is a secret worker lease issued once. Never expose tokens in a chat or public output.

1. `tick(conn)` returns `requested` with `work_id`, story and kind; it can also return existing `preparing`, `reconcile`, a review, or a no-work decision. A requested reservation can be picked up by another invocation after a crash. `claim(conn, work_id=..., owner=...)` returns state `preparing`, `id`, `story_id`, `version`, `kind`, `expires_at` and `token` to exactly one claimant. A second claimant sees `unavailable`. A lost successful claim receipt recovers by lease expiry and bounded retry. Use an isolated workspace per attempt, bind both editions to the stable story ID and read attributed evidence rows with positive `evidence_version <= version`. Keep the reserved inputs with the draft.
2. `refresh(conn, token=...)` rechecks eligibility and extends the bounded pre-push lease when it returns `preparing`. A preparing response with a `blocked` archive reason renews the lease while verification waits for a fresh snapshot. Other states stop this worker. A concurrent choice, new material, manual attachment or closed fallback slot can supersede it. Stage 5 must fence all external effects behind final authorization; obsolete workers may clean only their own drafts. Report generation/quality failure through `fail_preparation(conn, token=..., reason=...)`. Failure or abandonment adds an exponential per-story retry delay (initially 600 seconds, capped at six hours). Lower-ranked work can advance during the delay. Inspect deferrals in `dispatch-status`.
3. For a manual draft, stage 5 resolves the stable event identity first (or creates a private manual story). Call `attach_manual_preview(conn, story_id=..., version=..., preview_id=...)`. Use a globally unique immutable preview ID per draft. A withdrawn or replaced ID cannot be attached again. A waiting preview suppresses only the matching revision and holds no worker. New evidence lets the new revision compete and permits attaching its replacement draft. To withdraw it call `release_manual_preview(conn, preview_id=...)`. After stage 5 authenticates and durably records explicit human approval of the exact draft, call `reserve_manual(conn, preview_id=..., version=...)`. Persist approval before reservation. A retry returns only this draft’s work or a scoped outcome. A manual reservation and claim carry the immutable `preview_id` and version. Load exactly that approved draft and verify its approved artifact digests before push, including when recovering a reservation through a scheduled tick. For `busy` retry after the current worker finishes, for `deferred` respect `retry_at`, and for `blocked` refresh the archive. A stale preview requires a fresh approval. Automatic mode and pause controls preserve manual reservations. An approved manual reservation uses the same `claim`, `refresh`, manifest and verification steps. Stage 5 owns the manual approval receipt and draft-identity checks. No review callback, automatic tick or numeric rating can call this path implicitly.
4. After both German editions pass generation and quality checks, prepare an exact local commit. `authorize_push(conn, token=..., commit=FULL_GIT_SHA, manifest=...)` rechecks the worker lease, evidence version and archive for all work, plus slot, review, mode and automatic pause for automatic work, before atomically storing the intended commit and manifest. A preparing response with `push_once=false` and a `blocked` reason permits another authorization check with the same lease after archive refresh. The manifest has exactly three fields. `story_id` equals the reserved ID. `files` maps every repository-relative public artifact below `output/` to its lowercase SHA-256. `editions` maps `A2` and `B1` to distinct German canonical paths, for example `/articles/story-a2/` and `/articles/story-b1/`. Stage 5 verifies every staged change belongs to the attempt, both editions carry that story ID, and the commit contains exactly the recorded files with those bytes. Optional translations/media follow the existing publisher policy. The first authorization returns `push_once=true`. Only that response permits its single external push. Retries return `push_once=false`. Losing a response enters reconciliation.
5. Both `push-authorized` and `external-uncertain` hold the worker independent of lease time. After a timeout or restart read `status(conn)` for `work`, `expected_commit` and `manifest`. The trusted stage 5 verifier inspects remote ancestry, the actual remote manifest, deployment and both canonical edition identities. A later deployment can contain the expected commit. Call `reconcile(conn, work_id=..., commit=..., outcome=..., evidence=...)` with a short audit description. Use `unknown` for pending deployment, unreachable remote, ambiguous artifact identity or an interrupted push. Use `absent` only after fencing/terminating the authorized sender (including an in-progress remote operation) and definitively establishing that the expected external update did not occur. A timeout, old lease or temporarily missing pages cannot establish absence. Use `live` only on verified publication of the saved commit/manifest and both intended pages. The transaction calls `archive.record_publication_tx` and closes the work together. The first live verification advances the global clock once, including for manual work. Known final outcomes are idempotent; conflicting outcomes are rejected.

The operator checks effective approval tiers (including rating overrides) in `dispatch-status` plus `coverage` (source successes/errors) and `triage-status` (evidence holds and corrections). Run the offline fixtures on the installed host with `uv run pytest tests/test_editorial_dispatch.py tests/test_editorial_archive.py tests/test_editorial_triage.py`. Stage 4 includes no external publisher, editor transport sender or active scheduling installation.
