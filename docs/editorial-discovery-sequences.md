# Editorial discovery implementation sequences

The owner merges this branch. Local runtime verification is limited to the disposable collection/SQLite smoke in sequence 2. Write the remaining tests for the installed OpenClaw host. Each sequence has an isolated implementation, independent static adversarial review, and a separate remediation pass for findings.

## 1. Registry and database

1. Preserve every ID and URL in `config/civic_sources.json`. Classify each endpoint explicitly for polling (feed, HTML listing, document index, changing notice) or lookup (including contact and subscription). Provide an editable cadence, active flag and geographic scope, retaining uncertainty where a source covers multiple jurisdictions. One network endpoint can have several issuers; changing a single issuer's address must not lose another's cursor.
2. Add a small package at `scripts/editorial/`. Implement a SQLite connection factory with configurable database path outside public output, UTC epoch times, foreign keys, explicit short transactions, busy timeout and versioned migrations. Supply durable settings, source/endpoint relationships, cursor, failure and baseline state. Provide stable endpoint identity independent of the URL; a changed address must be rebaselined safely. Later migrations must work on an existing host DB.
3. Build registry validation and transactional reload. A malformed reload rolls back. A paused or removed source stops polling while preserving history. Reject duplicate IDs, unusable URLs and incompatible settings for shared active endpoints. Expose a command to sync, inspect adapter coverage and initialise state. Use `pyproject.toml` for the console entry point, and `python -m scripts.editorial` for development. Check how `config/sources.yaml` supports the existing manual workflow before touching it.
4. Provide host tests under `tests/` for all 159 inventory entries, stable reload, shared endpoints, pausing, editing and migrations. Document operational defaults in code/config as needed. No ingestion, LLM, review or publishing logic in this increment.

Acceptance: the source inventory reconciles to 151 original entries and eight additions; lookup-only rows remain identifiable; reloads preserve identities and historical state. The next sequence can obtain due endpoint records and update cursors transactionally.

## 2. Collection and disposable local verification

1. Extend `scripts/editorial/db.py:MIGRATIONS` with the report, revision and source-sighting relations. Expose an `editorial_inputs` view returning a stable revision ID, title, URL, publisher, published_at (nullable UTC epoch), observed_at, evidence and an eligibility bit. Preserve cross-feed attribution. A second issuer repeating a wire item cannot create a second version of the same text at the same canonical address.
2. Build `scripts/editorial/collection.py` and adapter helpers against `registry.due_endpoints` and `registry.update_poll_state`. Fetch outside write transactions. Recheck the endpoint snapshot and commit all observations and its cursor together. Handle RSS/Atom, dated listing links, document links, and notices at fixed addresses. Extract actual article content for listings, constrain navigation to relevant published items, and surface usable coverage gaps for inaccessible or unsupported endpoints. Set limits for per-host requests, response size, number of child links, redirects and timeouts. Support 304 and Retry-After. Track GUIDs, URLs and meaningful text revisions independently of wrapper timestamps.
3. On first import, baseline earlier items; allow an explicit bounded lookback for already recent dated material. Historical discovery and unchanged pages never become new breaking news. Resume failed child pulls without skipping undelivered content. Provide a collection pause switch and JSON CLI through `scripts/editorial/__main__.py`; document the commands for later OpenClaw skills.
4. Write offline regression cases for host execution. Provide `python -m scripts.editorial.smoke` that makes its own temp state, imports the real registry, fetches representative named sources (including outside Berlin and all supported adapter families), reopens SQLite and polls again to distinguish sightings from duplicate revisions. Print aggregate counts, source/adapter errors and disposal result only. Use the existing environment. Run only this smoke locally. All downloaded contents, cursors, DB sidecars, logs and caches go in the disposable directory; remove it on success or failure.

Acceptance: at least one real report is persisted and re-read; a repeat does not manufacture a new revision; unreachable sources are identified honestly and independently; each implemented adapter family has an attempted sample. Confirm disposal before the stage closes.

## 3. Triage and archive

1. Add migrations in `scripts/editorial/db.py` for stable stories, editions, revision evidence, model decisions, editor feedback, and persistent single-worker leases. Expose story status, evidence version, score, deadline/expiry and relationship for dispatch. Store model scores and overrides separately. Provide one transaction API for recording a uniquely identified verified publication for the scheduler, with a clear distinction between archive bootstrap and newly observed publication.
2. Implement `scripts/editorial/archive.py` and an archive-sync CLI. Reconcile recursive `output/**/_posts/*.md`, YAML front matter, translations and canonical edition URLs against the live sitemap. Support a local sitemap fixture for host tests and fresh host bootstrap. Prefer explicit shared IDs. For older posts use the already researched public edition mapping from `/private/tmp/bb-public-audit/tables.json` (editions sheet), retaining only public paths and group IDs in a small versioned data file, flag collisions and unmatched claims. Fail closed when live evidence is unavailable. Seed fallback once from known live time or an explicit bootstrap epoch and don't advance it for editions or redeploys.
3. Implement `scripts/editorial/triage.py` and CLI claim, decide, status and held-case resolution for OpenClaw. Select eligible unprocessed revisions from `editorial_inputs`; return short evidence with URLs, shortlist both pending and published events by normalized title, topics/entities, dates/place including older distinctive matches, and a durable bounded lease. Perform LLM work outside SQLite. Require reference to a supplied candidate for same/follow-up/correction. Support multiple events from one source. Validate JSON, true integer score 0–10, evidence attribution and expiry, bounded invalid-response retry and human resolution on uncertainty. Retried/late results cannot mint new stories. Preserve original queue age, editorial holds/dispositions and old scores, freeze evidence already in publication, keep live duplicates as observations, flag material corrections, allow distinct follow-ups.
4. Ship the OpenClaw triage skill with versioned rubric, output contract, replay examples and feedback persistence. Treat source excerpts as evidence only. Give every source the same rules. Preserve explicit wire attribution, independent factual support, Berlin consequence and time sensitivity. Spandau is the confirmed 8 anchor; distinguish proposed anchors 10, 5 and 2. Include replay/holdout cases and guidance for using historic dates.
5. Write host tests under `tests/` for archive identity/nested posts, collision, same event across sources, stale/duplicate lease, material changes, live repeats/corrections, follow-up, uncertain and malformed outputs, and feedback. Document exact host commands and contracts used by the scheduler. No local runtime for this sequence.

Acceptance: the freshly installed host can bootstrap the live archive, request a bounded evidence packet and submit the model's structured judgment. SQLite atomically records the outcome and exposes enough information to select an eligible story, preserve editorial decisions and recover from a retry.

## 4. Scheduling and editor review

1. Extend `scripts/editorial/db.py:MIGRATIONS` with durable review requests, editor-action receipts, work claims/reservations and transitions. Build `dispatch.py` plus CLI additions consumed by a host-only OpenClaw review skill. Configuration in `config/editorial_policy.yaml` supplies five-minute ticks, 12-hour slot and Tier 2 review interval, bounded leases/holds, archive freshness, observation by default. Persist mode/publish-pause independently of collection. An empty/failed/stale archive or unresolved external publication outcome inhibits real dispatch; previews may explain why. Obtain wall clock exclusively on host, accept injected times only in Python tests.
2. Within short `db.transaction` sections, derive queue eligibility from `editorial_queue`, `archive_ready`, `archive_checked_at` and `fallback_epoch`. Check expiry/deadline, evidence, status, human holds and version. One writer claim at once. Tier 0 immediate, highest score then freshness; otherwise at exactly 12h, tier 1 by score, impending deadline, freshness and stable ID; otherwise one tier 2 card in same slot. No elapsed clock updates except `archive.record_publication_tx`. Manual/T0 success closes the same slot. Attach new material safely, expire/reconsider via documented fresh evidence procedure. No endless Tier 2 requests after a decline. Observation must support exercising decisions without publishing or contacting an editor automatically.
3. Persist distinct requested/preparing/push-authorized/external-uncertain states. Supply stable APIs for stage 5 to claim, refresh, supersede, check eligibility and atomically persist an expected commit/manifest before external push, and reconcile known outcomes. Prevent concurrent ticks, duplicate fallback reservations, lease expiry during unresolved push, stale authorization, fallback overtaken by Tier 0, and failure starvation. A waiting manual preview must not hold the publication worker. Track deferred items through retries.
4. Implement immutable revision-bound review cards containing the case, score, impact, date, rationale and source URL. Authenticated editor identity comes from host transport metadata and a configured allowlist, callback event ID included; bind to request and story/evidence version, reject others. Implement approve, decline, hold, rate, explicit rate-and-publish, retries and stale replies. Rating alone cannot clear the Tier 2 approval requirement even if moved to score 9. Expose pending/resend acknowledgments without treating delivery as approval. Integrate earlier lower-level feedback/held-case interfaces where appropriate. Do not send messages locally.
5. Ship skill instructions, JSON status and host tests for timing boundary (including DST), observe/pause/resume, concurrent dispatch, stale evidence/approval, out-of-band manual live clock, abandoned pre-push vs ambiguous push, expedited Tier 0, ratings and replayed editor actions. Document the exact stage 5 integration contract in `docs/editorial-dispatch.md`. No runtime checks locally.

Acceptance: after fresh live reconciliation, one SQLite transaction decides dispatch or editor review for the global slot. Replays cannot double-publish, and only a trusted affirmative action can dispatch an item awaiting human approval.

## 5. Publication integration

1. Connect the real manual and automated publication entry points to the same SQLite ledger using the transaction API in `docs/editorial-dispatch.md`. Add publisher CLI and an OpenClaw publishing skill. Create a private per-attempt Git worktree from fetched `origin/main` and bounded state directory. A manual preview belongs to a unique draft ID and evidence version, uses no global worker during editor wait, remains editable through existing `bb stories`, `illustrate`, `add-image`, and `preview`, and publishes only on explicit approval of that exact draft. Preserve the manual `bb received/generate/preview/publish/discard/status` UX and split-paste/notification behaviors. Inspect and handle the pre-install `.bb-pending` safely during upgrade. Reuse existing private source, quality, translations, illustration and audio helpers. No broad staging/cleanup in a shared checkout. Persist private state across restarts. A failed partial generation retains its source for bounded retry.
2. Add a stable optional `--story-id` to `scripts/manual_pipeline.py` for reserved work; defaults still work for existing standalone callers. Use both German levels, require one of each with matching ID, include only their related translations/illustration/files and optional audio following current rules. Feed generator frozen attributed evidence via private input; public prose/metadata should not expose private input or state. Manual matching must occur before a competing automatic push: offer the existing matcher shortlist and a concrete manual decision for ambiguous matches, then attach or create one event. Ensure retries, manual callback IDs, released previews, changed evidence and concurrent Tier 0 are fenced.
3. At approval/pre-push restamp article front matter and matching translation publication times using the real Berlin publication window; handle midnight/date-slug and preserve URLs/media relationships, avoid future dates. Use repo `scripts/publisher.py` and existing News sitemap time conventions. Emit a machine-readable story ID on public article pages for deployment verification. Keep optional image/audio policies, podcast integrity and compatibility with existing posts; no generation, pushes or media calls locally.
4. Define an allowlisted, verified manifest from story-specific worktree changes. Before push verify actual commit delta and strong per-file hashes, A2/B1 canonicals and identity. Record full expected SHA/manifest using `dispatch.authorize_push`, fence sender with OS lock, push exactly the recorded commit to main without force. If origin changes before authorization, rebase/refresh safely and recompute SHA/delta. Never blindly replay an uncertain external transaction. Implement noninteractive restart reconciliation via read-only Git/GitHub Pages and public canonical fetch: expected SHA in remote and deployed commit ancestry, expected manifest blobs at deployment, both live pages identify the intended story, then `dispatch.reconcile` once. Timeouts/ambiguity remain pending. Provide safe definitive-negative recovery where evidence permits it or documented explicit operator reconciliation for ambiguous receipts.
5. Document entry points and recovery in `docs/editorial-publication.md`, manage missing credentials and isolated host paths without importing secrets into Git. Add host-only regressions for pending manual plus unrelated T0, exact-match manual suppression, duplicate approvals, partial pairs and wrong-story artifacts, midnight/old previews, push receipt loss, unrelated and later deployments, existing manual upgrade and clean recovery. Stage is complete when the normal `bb` skill, scheduled path and operator recovery can use the real code with a single live ledger. Do not run project/runtime tests locally.
