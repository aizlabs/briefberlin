---
name: briefberlin-illustrate
description: Create editorial illustrations and data charts for quality-approved Brief Berlin stories. Use during agent-driven generation or when adding visuals to an existing article.
---

Find the generated post(s) in `output/_posts/` from the current run or the user's selection. Group editions by their exact `story` front matter. An A2-only or B1-only run is sufficient. If a legacy post has no story ID, ask which editions belong together before assigning one. Skip dry runs.

For each story:

1. Read the final public German headline, summary and body. Choose **one visual by default**. When the main point is a comparison, change over time or a numerical breakdown, make a chart the lead visual. A story that simply mentions numbers can still work better with an illustration. Add a second visual only for a distinct point that helps the reader understand the story. A third is exceptional. Count existing editorial images and charts, including any in the body, toward the **maximum of three per edition**.
2. Check `output/_data/story_illustrations/<story>.yml` and the existing assets. Reuse suitable visuals, including on retries. Every shared visual must fit every edition it appears in. Keep private source files, URLs and drafts out of prompts and public assets.
3. **For an illustration**, choose a subject and action an A2 reader could recognize. Preserve distinctions such as a proposal versus a decision. Choose a medium, light and palette for this specific story. Quiet gray graphite can suit mourning, colorful watercolor can clarify a public space, and photorealistic scenes can show everyday objects or services. Draw color from the subject and check adjacent stories for repetitive art direction. Use the agent’s image tool for a wide, mobile-readable composition. Give generated photorealistic scenes the visible German caption “KI-generiertes Symbolbild”. Omit lettering, logos and invented documentary details. Inspect the result and save a web-sized landscape WebP. If the tool is unavailable, report the skipped illustration and leave the article publishable.
   **When a real person is the subject**, lead with a reference-based photorealistic portrait. Prioritize the person the headline and story are about over incidental mentions. Search credited public sources whose captions name the person and match their role. Open the original file page, verify the credit and permission for adaptation and publication, and supply the actual reference image to the image tool. One well-documented reference can suffice. Preserve the likeness and expression in a neutral portrait. Compare it with the reference before publication. If references are ambiguous or the likeness is unreliable, use a verified reusable photograph or a story-specific nonportrait. Label the adaptation in German and include the photographer, changes, source link and applicable license in the visible caption. For the layout, use `source_url`, `credit`, `license_url` and `license` on the visual record.

4. **For a chart**, extract values, units, groups and periods from the approved public text. Compare like with like. Use a horizontal bar chart for categories or a line for a series over time. Start bar lengths at zero. Preserve qualifiers such as “rund” and distinguish percentages from percentage-point changes. Render the data with a plotting or vector tool so the geometry and labels match the values. Use short German labels and direct values that remain legible at phone width. If the data cannot support a meaningful chart, choose another visual.
5. Save assets in `output/assets/images/stories/` with the story ID in each filename. The YAML record contains a `visuals` list in reading order. Each entry has a site-relative `path` and German `alt`. Add `caption` when the image needs a visible label. Describe the visible action for an illustration. For a chart, state the main comparison and essential values in accessible language. The post layout places the lead below the summary and supplementary visuals after the text.
6. Open the assets, cross-check chart values against the public text, and verify paths and the visual count for each matching German post. Report the chosen visuals and any skips to the calling flow. Follow its existing publication instructions.
